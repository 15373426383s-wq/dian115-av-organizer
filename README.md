# 番号整理（DIAN115 第三方插件）

按番号识别、刮削并整理视频。识别、刮削、命名、NFO 与移动全部由插件完成，不使用宿主的 TMDB 整理；宿主提供文件操作、监听、网络、通知、FFP、图像处理、AI、图片标记、Emby 与 STRM 能力，插件负责业务编排。

当前版本 **1.4.3**（swgzy 维护版，基于 1.3.0，并借鉴 [MDC-NGi](https://github.com/li-peifeng/NGi) 的部分设计），需要宿主插件 API **3.5**。界面采用 Liquid Glass 风格，跟随宿主明暗主题；桌面使用侧栏导航，小屏使用横向导航。文件浏览、目录选择、115 账号、下载器、馒头站点、Emby 服务器与媒体库、AI 提供商与模型均使用现有插件平台接口。

验证结果见 [1.3.0 页面与选择器验证](docs/ui-validation-1.3.0.md)。

## 1.4.3 修复：默认带 Accept-Language（JavBus 不再要求答题）

- 引擎默认给请求加 `Accept-Language: zh-CN,zh;q=0.9,ja;q=0.8,en;q=0.7`；HTML 来源再加标准 `Accept`。JSON 接口不写 `Accept`，避免内容协商问题。
- 原因：JavBus 在缺少 `Accept-Language` 时把请求当机器人，302 到 `/doc/driver-verify` 答题页；补上后直接返回正文（实测 302 → 200，50KB 正常页面）。来源规则里写同名头仍然优先。
- 顺带：这条规则同样改善其它按语言头做风控的站点。

## 1.4.1 / 1.4.2 修复：FlareSolverr 改用直连 request.get

- 挑战页兜底改为**直连** FlareSolverr 兼容服务：`POST <endpoint>/v1` + `cmd=request.get`，并显式 `proxy: direct`（F 盾在内网，不走外网代理）。只实现 `request.get` 的实例（如 F 盾）也能用。
- **不再走宿主 `render`**（它会先 `sessions.create`）：部分实例在该调用上会卡住甚至被拖死；配了端点时只用直连，失败就直接返回原始响应，让该来源快速失败，不拖累整轮整理。未配端点时才交给宿主 render（宿主可能已内置 FlareSolverr）。
- **修复字段映射 bug**：宿主 `render` 返回 `html`，而来源解析读 `response.body`，导致挑战页即使渲染成功也解析为空；现在两条路径统一成 `{status, body, url}`。
- 直连预算 = 来源请求超时 × 2，封顶 120 秒。

## 1.4.0 借鉴 MDC-NGi 的三处改动

[MDC-NGi](https://github.com/li-peifeng/NGi) 是同类刮削整理工具。对照它的功能清单，这里只补了本插件真正缺失的三点，未引入与宿主能力重复的实现（整理模式、目录监控、人脸裁剪、水印、NFO、字幕库本插件已有）。

- **本地翻译缓存**（对应 NGi「内置中文标题数据库」）：同一番号的同一段原文只翻译一次，重新刮削、换目录或换模板时直接复用，省 AI 额度也更快。缓存键包含番号、翻译引擎、目标语言、模型、补充要求和原文，任一项变化都会重新翻译；默认 90 天过期、最多 600 条，按写入顺序淘汰最旧条目。「设置 → 翻译与完整性」可关闭或一键清空。
- **多来源资料精选**（对应 NGi「多来源数据手动精选修正」）：整理记录的「编辑资料」里，每个来源一张卡片，显示来源名、标题、演员、日期、厂商与封面缩略图，点「采用此来源」即把该来源字段填进表单，确认后写入 NFO；「当前采用」标记可看出这条记录原本用的是哪一家。原始字段仍保留在折叠区。
- **整理记录批量重新刮削**（对应 NGi「批量重试」）：记录列表支持勾选，「全选本页」「批量重新刮削」一次提交多条重新刮削任务，只对已整理且保留了元数据目录的记录生效，之后可在任务队列查看进度与结果。

## 安装与配置

在插件中心上传 `av-organizer-1.4.3.dian115p` 安装或更新。插件 ID 保持 `local.av-organizer`，升级保留原设置、订阅和历史记录。

1. 在「设置 → 基本」选择工作模式、收件目录与整理目标。目录通过本地/CD2 文件浏览器选择，支持筛选、排序和新建文件夹。
2. 在「刮削来源」选择来源与顺序，按需配置登录状态。来源字段优先级通过选择和排序设置。
3. 需要订阅时，在「番号订阅 → 订阅设置与查询源」选择 115 账号和保存目录、下载器与馒头站点。备用账号必须选择目录；切换账号后重新选目录。
4. 演员同步在「设置 → 演员资料」选择 Emby 服务器与媒体库；翻译在「翻译与完整性」选择 AI 提供商和模型，并保持「复用本地翻译缓存」开启。缺失或读取失败的选项保留原值，不自动改成其他配置。
5. 在「文件管理」勾选文件或目录，创建仅对本次生效的整理任务；常规批量整理使用「立即整理」。

115 保存目录按节点 ID 读取，远端文件夹名称作为完整文本处理。选中的账号随提交意图一同保存，重复提交判定和中断核对使用相同账号。账号与目录选择只影响离线提交；媒体整理仍使用本地/CD2 路径。

- 演员列表、每小时分页同步、成功/失败记录；可用自定义 JSON 演员资料库精确匹配并写回 Emby 简介及头像；未配置资料源时请求 Emby 自身提供商刷新，记录为“已请求刷新”，不冒充已刮削成功。

设置按需开启。AI、演员同步、水印和 Webhook 默认关闭。

最近的来源核对包含 26 个来源，其中 17 个来源的测试样本取得元数据与可解码封面；其余访问限制见 [联网验证记录](docs/scrape-validation-1.2.4.md)。演员同步分别判断简介和头像是否缺失，默认请求宿主支持的 `Default` 刷新；「已请求刷新」表示请求已提交，不表示 Emby 已完成抓取。

### 已知边界

站点受登录、地区和页面变化影响，内置来源不保证在所有网络中可用。Graphis/Minnano/Tenhow 的具体页面可使用 HTML/补充海报规则配置，未内置其全量人物映射或完整自动搜索。模板支持常用 Jinja 语法，不提供 Python 执行、文件 include/import 或完整 MiniJinja 扩展。外部种子数据库通过 HTTP/JSON 服务接入，新增 SQLite 仅用于插件自有静态资料；不提供 MySQL/PostgreSQL 原生连接。硬/软链接仅支持 CD2 挂载外本地路径；FFP 不接受任意 URL/STRM；ICO badge 原图可读但不能合成。

## 番号订阅

在主程序的 Telegram 机器人中发送 `av SSIS-001 MIDV-100`，也支持 `AV `、全角空格、`/av` 和 `/av@机器人名`。只要识别到番号，先加入**本插件的独立订阅**，无需先刮削元数据或搜到种子；随后立即并发搜索。多个番号一起发送会规范化、去重，重复消息保留原订阅。消息触发目前使用宿主实际提供的 Telegram 插件桥接，不代表任意聊天软件都能触发；消息若先被宿主内置命令或链接识别处理，不会再交给插件。

- 缓存：直接复用宿主磁力 / ED2K 缓存增量接口，不读取宿主数据库文件。
- 数据库查询源：用户配置一个或多个 HTTP/JSON 查询接口，每个来源选择提交到 115 或主程序下载器。它不是 MySQL/PostgreSQL 原生驱动；当前插件后台没有公开 TCP/SQL 驱动能力，原生数据库需要由现有服务提供 HTTP 接口，具体适配需数据库类型、字段或接口样例。
- 周期：宿主每分钟检查到期订阅，默认每个番号间隔 60 分钟，默认每批最多 50 个番号、同时处理 3 个番号（页面可改并发为 1–8）。每个番号的多个查询源并发请求；来源顺序决定优先选择，单源失败不阻断其他来源。
- 结果：只接收番号字段或标题明确匹配的资源。第一次确认提交后显示“已提交”并停止自动搜索，记录仍保留；不等同于下载完成。可以手动“继续寻找其他资源”，跳过已有提交记录。没找到、来源未配置或查询失败时保留订阅，下次继续。
- 115：磁力/info_hash 与 ED2K 直接创建离线任务；HTTP `.torrent` 先读取原始 bencode info 字节计算 SHA-1，转为磁力后提交，避免误把种子文件本身作为普通下载。HTTP 种子限制 4 MiB，损坏种子或 HTML 登录页不会提交。通过选择器指定主账号或备用账号及保存目录；主账号可沿用默认离线目录，备用账号必须选择目录。
- 下载器：通过主程序 PT 下载接口提交磁力或种子 URL，从主程序已配置的下载器中选择，默认项使用主程序默认下载器；保存目录遵循下载器在主程序里的配置。
- 去重与中断：插件 KV 使用版本比较更新，不靠某次 JS 运行的内存锁。外部提交前保存意图，按目标和种子 hash（缺失时按来源+资源 ID/URL）记录去重。超时/连接中断不能证明未提交，进入“需要核对”并阻止重发。重启后通过任务的“核对并继续”查询 115 的 hash；无法确认、查询不到或下载器不支持精确目标核对时，须在订阅页确认“已提交”或“未提交”后继续。
- 生命周期：关闭插件页面不停止订阅。暂停自动搜索仍保存收到的番号；停用整个插件由宿主取消消息/定时任务，卸载清空插件状态，不撤销已提交给 115 或下载器的业务。

“番号订阅”标签包含添加、立即搜索、暂停/恢复、取消订阅、状态、错误与结果核对。“订阅设置与查询源”单独保存到插件的加密 KV，不影响原整理设置。默认启用宿主磁力 / ED2K 缓存，命中后自动提交 115；外部数据库和馒头需另行配置。

### 数据库 HTTP 接口示例

在查询源编辑器添加（域名是占位示例，需替换）：

```json
[
  {
    "id": "seed-db",
    "name": "种子数据库",
    "enabled": true,
    "url": "https://database.example/search?number={number}&since={since}&until={until}&cursor={cursor}&limit={limit}",
    "incremental": true,
    "complete_path": "complete",
    "cursor_path": "next_cursor",
    "method": "GET",
    "headers": { "Authorization": "Bearer 在插件设置内填写" },
    "results_path": "items",
    "target": "115",
    "fields": {
      "number": "number",
      "title": "title",
      "magnet": "magnet",
      "ed2k": "ed2k",
      "download_url": "torrent_url",
      "info_hash": "info_hash",
      "id": "id",
      "seeders": "seeders"
    }
  }
]
```

接口返回数组所在位置由 `results_path` 指定（如 `data.rows`，根数组用空字符串）；字段支持点分路径。默认响应：

```json
{
  "complete": true,
  "next_cursor": "",
  "items": [
    {
      "id": "resource-1",
      "number": "SSIS-001",
      "title": "SSIS-001",
      "magnet": "magnet:?xt=urn:btih:0123456789abcdef0123456789abcdef01234567"
    }
  ]
}
```

`magnet`、`ed2k`、`torrent_url`、`info_hash` 至少有一个有效值；没有 number 时，标题或 ED2K 文件名须包含精确番号。`target: "downloader"` 将磁力和种子 URL 提交下载器；ED2K 始终交给 115。POST 可设置 `body: {"number":"{number}","since":"{since}","until":"{until}","cursor":"{cursor}","limit":"{limit}"}`，支持嵌套值。最多 10 个数据库源，响应最多 4 MiB / 1000 条，超出报错而不截断推进。

启用 `incremental: true` 时必须把 `{since}`、`{until}`、`{cursor}` 传给来源端；来源按 `[since, until)` 时间范围过滤，返回布尔 `complete`，未完成时返回可推进的字符串 `next_cursor`。插件每轮读一页，保存固定窗口和游标，下轮续读；`complete=true` 即使空结果也推进基线。旧接口不设 `incremental` 继续按原方式查询，页面显示“传统接口，尚未启用增量”。仅追加时间参数不会自动获得增量能力，来源端必须实现过滤。

种子 URL 必须可直接访问或带短期下载签名；查询接口的 Authorization 不会被复制到其他种子域名或下载器。把真实凭据填在安装后的插件设置里，不要改进源码、样例或提交到仓库。馒头的下载令牌由主程序的站点适配器处理。

## 两种整理模式

| 模式 | 视频 | NFO / 封面 / 字幕 | 刷新 |
| --- | --- | --- | --- |
| 纯本地 | 本地整理目标 | 与视频同目录 | 插件调用 Emby 刷新 |
| CD2 + STRM | 所选 STRM 规则的源目录（CD2） | 该规则输出目录的同一相对位置 | 宿主生成 STRM 并刷新；规则不是实时同步时插件触发一次增量同步 |

CD2 + STRM 模式下元数据不上传云盘。宿主按"输出目录 + 视频相对源目录的路径 + `.strm`"生成 STRM，插件用同一个相对路径写入 `番号.nfo`、`番号-poster.jpg`、`番号-fanart.jpg`，文件名前缀与 STRM 一致；源视频删除时宿主的同名元数据清理也能对上。建议把规则的元数据同步设为"不同步"，否则云盘上的同名元数据会覆盖本地 NFO。收件目录最好与规则源目录在同一个云盘，CD2 服务端移动更快。

## 流程

1. 扫描收件目录（目录监听触发，另有每 30 分钟的定时扫描兜底）。小于最小大小或刚修改过的文件本次跳过。
2. 认番号：清理站点前缀（含 `站点@站点@番号` 写法）、分辨率、编码、体积等噪音后按规则表识别：有码（含 `ssis.001`、`SSIS—001`、全角写法）、DMM 内容编号（`118abp00123`、`h_1133honb00123`）、前缀带数字（T28、S2M、R18、3DSVR）、编号带字母（MKBD-S123）、FC2 各种写法、HEYZO、HEYDOUGA、Tokyo-Hot、加勒比 / 一本道 / 10musume 日期编号、带数字前缀的素人系列。分段识别 CD1、pt1、part2、`-A/-B`、`_1/-2`、`(1)`；相机、录屏文件名和普通英文单词加数字不会被误认。规则由 `test/corpus.test.mjs` 的乱文件名语料库约束，改规则先跑一遍。文件名认不出时用上一级目录名；认出多个番号或认不出时交给第 4 步的模糊匹配。
3. 刮削：按"设置 → 刮削来源"的顺序，只查询已启用且支持这个番号类型的来源，**只接受番号完全一致的结果**。"快速"模式取到第一个完整结果就停，"完整"模式最多查询 N 个来源（默认 6）后按字段优先级合并，类别、演员合并去重；详情里记录每个字段来自哪个来源。结果按番号缓存 7 天。
4. 认不出精确番号时自动模糊匹配（可在设置里关闭），全程不需要人工：
   - **宽松番号**：认出多个番号，或只有不规范写法（`ssis001hhb`、`abc 12`）时，逐个刮削确认番号真实存在，再用去掉番号后剩下的文字（标题线索）比较站点标题。两位数编号必须达到阈值。
   - **关键词搜索**：完全没有番号时，用标题线索在已启用、支持关键词搜索的来源（最多 4 个）里搜索，按匹配度挑选。
   - **采用条件**：第一名匹配度 ≥ 阈值（默认 85），且比第二名高出领先差距（默认 5 分），防止同系列相近标题选错；不满足时留在待确认，并列出各候选的匹配度。
   - **匹配度** = (相似比 + 覆盖率) ÷ 2 × 100：相似比看两段文字整体有多像，覆盖率看文件名里的字有多少出现在标题里；忽略全半角、大小写与标点。文件名就是完整标题时为 100，只写了前半段标题时约 80 多。
5. 生成目录和文件名，目标已存在则跳过并留在待确认，不覆盖。
6. 先写 NFO、封面、字幕，再移动视频。
7. 本批有成功时刷新 Emby（纯本地）或触发 STRM 规则同步（CD2 + STRM，非实时规则）。

## 自定义清理

设置里的"自定义清理规则"每行一条，先于内置清理执行，识别番号和模糊搜索都使用清理后的文字：

```text
# 去掉固定的站点前缀
@私人收藏
# 正则去掉匹配内容
/\bhhb\d*\b/i
# 替换（可用 $1 等分组）
XYZ => SSIS-
/^\[(\w+)\]\s*/ => $1 
```

写错的正则会在任务日志和试识别里提示，并被跳过。

## 任务队列

整理任务在宿主任务队列里显示为"番号整理：整理收件目录"，进度按"已处理 / 总数"计算，失败数为留在待确认的文件；单个文件移动的进度写在当前状态里，不会让整体进度条来回跳。"测试匹配"不进任务队列页面。当前版本需要宿主插件 API 3.5。

待确认的文件会自动重试：失败后 1 小时再试，之后每次间隔翻倍，最长 24 小时；文件有变化时立即重试。整理被宿主重启打断时，概览里会出现"核对并继续"，核对前宿主不接受新的整理。

## 页面

插件页包含概览、整理记录、待处理、识别测试、番号订阅、文件管理、演员资料与设置八个页面：

- **概览**：已整理、今日整理、待处理、已忽略、模糊识别、移到失败目录等统计；运行状态（工作模式、收件目录、整理目标、目录监听、当前任务进度、上次整理）与“立即整理”“重试全部待处理”“启用 / 停止目录监听”；被宿主重启打断时的“核对并继续”；各数据来源命中比例；最近整理的封面墙。
- **整理记录**：按番号、标题、演员、标签、路径搜索，按状态与识别方式筛选，列表与封面墙两种视图、分页。点开是详情抽屉：海报、标题与原标题、演员、标签、发行日期、时长、厂商、发行商、系列、导演、简介；识别方式与匹配度、中字 / 破解 / 4K / 分段标记；每个数据来源的原始页面链接；来源文件、视频、元数据目录、NFO、海报、背景图、剧照、字幕的完整路径（可复制）；处理日志与耗时。可以“重新刮削”（不走缓存，覆盖 NFO 与图片，不移动视频）。
- **待处理**：失败原因、尝试次数、首次与最近失败时间、下次自动重试时间、识别过程（清理后文字、标题线索、宽松候选）与候选匹配度。可以点候选填入番号后“按番号整理”、直接“改名”（实时预览新名字的识别结果）、“立即重试”、“移到失败目录”、“忽略 / 取消忽略”，查看日志。
- **识别测试**：按当前设置逐步显示自定义清理、内置清理、精确番号、宽松候选、标题线索与标记；“测试匹配”与整理走同一流程，显示是否会自动整理、方式、匹配度、封面与元数据；“来源检测”逐个来源按番号取详情，报告可用性与耗时。
- **设置**：基本（工作模式、收件目录、本地目标或 STRM 规则下拉、失败目录）、命名（模板与实时预览）、识别（自定义清理与实时报错、模糊匹配阈值滑块）、刮削来源（合并模式、来源数量、代理、CookieCloud、请求间隔、年龄确认；每个来源的启用、排序、单独测试、镜像地址、Cookie、令牌；自定义来源的编辑、导入导出与字段优先级）、元数据（封面、剧照、封面缓存、演员与标签映射）、运行。目录都可以用路径浏览器选择，本地目录和 CD2 云盘都能浏览、新建文件夹。保存前校验目录关系；修改收件目录时自动切换目录监听。

## 工作模式

| 模式 | 说明 |
| --- | --- |
| 刮削并整理 | 识别番号 → 刮削 → 生成 NFO、海报、背景图、剧照 → 按模板移动（默认） |
| 只整理不刮削 | 只按番号移动和改名，不联网、不写元数据，目录模板默认 `{prefix}/{number}` |
| 原地刮削 | 视频不动，NFO 与图片按视频原名写在视频旁边；已处理的文件不会重复处理 |

其他整理功能：剧照下载到 `extrafanart/`、标题最长字数、演员名与标签映射（`原值 => 新值`，新值留空表示删除）、连续失败 N 次后移到失败目录。

## 刮削来源

内置 26 个预设来源，每个来源是一份声明式规则（`ui/lib/presets.js`），由规则引擎（`jobs/lib/engine.js`）执行。站点改版时改规则即可，不需要改代码：

| 分类 | 来源 |
| --- | --- |
| 综合 | JavBus、JavDB、JavLibrary、Jav321、AVBASE、FreeJavBT、7mmtv、Airav.io |
| 官方 / 数据接口 | FANZA（DMM）、XCITY、R18.dev（DMM 数据）、AirAV、ThePornDB（需要令牌） |
| 素人 | MGStage |
| FC2 | FC2 官方、FC2PPVDB |
| 无码 | AVSOX、Caribbeancom、Caribbeancom Premium、一本道、天然むすめ、パコパコママ、HEYZO、Tokyo-Hot |

- **按番号类型分流**：有码、带数字前缀、FC2、加勒比日期编号、一本道系日期编号、10musume、HEYZO、Tokyo-Hot、HEYDOUGA 各自只查支持的来源，例如 `010124-001` 只去加勒比、JavBus、JavDB、AVSOX 等。
- **实时可用性**：来源保留实测结果，最近一轮验证见[全来源联网验证记录](docs/scrape-validation-1.2.4.md)；这不保证每个站点或作品当前均可访问。启用前可在"设置 → 刮削来源"里点该来源的"测试"，或在"识别测试 → 来源检测"里批量检测；不可用的来源可以停用，或"复制为自定义来源"后修改规则。
- **自定义来源**：用 JSON 写规则，保存前校验并可直接测试，支持导入导出。主要字段：`type`（html / json）、`kinds`（支持的番号类型）、`steps`（前置请求取变量）、`search`（搜索页与结果项）、`detail`（详情页地址，或 `search` 表示取搜索结果里番号一致的链接）、`rows`（"标签：值"信息行）、`fields`（`css`、`css@attr`，或 `{sel, attr, all, label, json, jsonld, re, replace, template, from, split, type}`）、`not_found`。地址可用 `{base}`、`{number}`、`{number_lower}`、`{number_nodash}`、`{cid}`（DMM 内容编号）、`{fc2_id}`、`{heyzo_id}`、`{date_id_underscore}`、`{token}` 等变量。
- **JSON 数据接口**：`steps` 可用 `sel/attr` 提取 CSRF，`shared_steps:true` 合并并发初始化；`search/detail` 可用 `method/headers/json_body` 发送 JSON 参数。`search.vars` 把命中项字段传给详情模板，`detail.from_search` 连接搜索和详情 API，`page_url` 保留可打开的页面链接，`response_code` 核对业务状态。`json_map` 可把演员姓名和头像转换为映射；`json_errors` 检查 API 错误列表，`detail.missing_json` 标记空详情；`search.exact_keyword` 只转换精确番号查询，普通关键词保持原文。`detail.page_pattern/page_vars/page_query/page_base` 将同站手工详情链接转为数据请求。日期字段可用 `timezone_offset`（分钟）转换带时区的时间戳，分钟字段自动识别时分秒。完整例子见 AVSOX 和 FANZA 预设。
- **字段优先级**：完整模式下选择字段，再添加和排序该字段的来源；未配置的字段按整体来源顺序。

## 站点访问

多数站点需要先通过年龄验证或登录，部分地区禁止访问。插件不绕过登录、验证码或地区限制：

- 在自己的浏览器里通过验证后，用 CookieCloud 或在来源里粘贴 Cookie。
- 可选开启"我已年满 18 岁"：按站点设置年龄确认 Cookie 或提交同站确认表单，默认关闭；FANZA 数据请求也遵循此开关。人工答题需要在浏览器完成后导入验证状态。
- 需要代理时填写刮削代理；使用宿主代理域名名单时，把启用来源的域名加进去。
- 遇到年龄验证页、Cloudflare 校验或地区封锁，测试结果会直接写明原因。

## 与内置整理的配合

收件目录不要放在宿主整理规则的源目录里，或把它加入整理规则的排除路径，避免宿主先用 TMDB 识别失败。可选开启"接手宿主整理失败且能认出番号的视频"：收到 `library_organize_fail` 事件后，插件把这类文件移进收件目录，由自己的流程整理。
