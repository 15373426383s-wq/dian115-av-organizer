# 整理与演员能力说明

本文说明插件的业务流程、资料源格式与功能边界。接口以宿主 `docs/plugin-platform` 的 API 3.5 文档为准。

## 能力范围

| 工作环节 | 插件实现 | 验证/限制 |
| --- | --- | --- |
| 扫描、过滤、监听、任务恢复 | 多目录独立配置、宿主监听加轮询、手动文件任务、并发 1–20、按文件预算 | 预算在操作边界检查；已开始的写入必须完成并确认 |
| 识别 | 严格番号、父目录、清理规则、模糊候选人工确认、字幕/破解/流出/分段 | 不把任意普通日期文件误当作品；动画/欧美日期型自动识别不作完整覆盖保证 |

## 演员资料的实际处理

1. 收到 Emby 人物条目，以原姓名和用户填写的别名建立可接受姓名集合。只接受规范化后精确一致；不做相似人名自动替换。
2. SQLite 默认静态资料的 `Names.Alias` 查 `Name`，再查 `Info.Name`；姓名没有唯一结果时失败。`Info` 的生日、身高、三围、出身地和活动时期用于简介，`Href` 保留为资料页线索。不能把数据库中的任意头像 URL 当作已经核实的另一人物。
3. Wikipedia 使用 MediaWiki query 的 redirects/extracts/pageimages/pageprops；接受精确页面名或从请求名到页面名的明确重定向，拒绝消歧义页，并要求简介符合演员身份。对百科不是完整人物消歧义系统，未命中会继续下一来源。
4. Gfriends 读取 `Filetree.json` 的 `Content[目录][姓名图片]`，精确匹配文件主名并按目录顺序组成候选。索引缓存 7 天；单个头像实际下载、检查尺寸、调用宿主 Emby 图片上传，损坏或失败则换下一候选。只缓存索引和需要的图片。
5. JSON 来源支持 `items_path/name_path/overview_path/image_path`。静态索引在任务中共享、按日缓存；带 `{name}` 的查询逐名请求。HTML 来源用 `name_selector` 核对姓名，再取简介和图片选择器；可用于已知 Graphis/Minnano 资料地址。
6. 来源逐字段合并，前面的简介可与后面来源的头像组合；来源和字段归属记入历史。简介与头像分别决定补缺/覆盖；未配置来源时只请求 Emby 自身提供商刷新，并明确记录“已请求刷新”。

例如，在演员来源配置中使用独立 SQLite 或现有 JSON 服务：

```json
[
  {"type":"sqlite","path":"actors/reference.db"},
  {"type":"wiki","language":"ja"},
  {"type":"gfriends","cache_days":7},
  {"type":"json","url":"https://example.test/actors?name={name}","items_path":"items","name_path":"name","overview_path":"biography","image_path":"portrait"}
]
```

默认资料库首次使用时按需下载，用户也可先上传到相同插件路径。自有数据库可指定 `table/name_column/overview_column/image_column`。这些查询仅访问插件文件区。头像索引与图片按需获取，不随插件包分发。

## 数据源解析流程

`ui/lib/presets.js` 保存各站规则，`ui/lib/registry.js` 负责启用、顺序、代理/UA/请求超时/重试参数，`jobs/lib/engine.js` 执行：

1. 将番号拆为标准值、FC2 ID、日期编号、DMM CID 等地址变量。
2. 执行可选 steps 获取详情 ID/链接；按搜索规则提取结果，或者请求由番号生成的详情 URL。
3. HTML 通过宿主选择器提取文本/属性；JSON 按路径提取；JSON-LD 从结构化脚本读取。支持标签行定位、正则、替换、分割、fallback、字段派生、日期/时长/URL 转换。
4. 搜索结果与详情番号再次核对。手动指定详情网址时强制要求详情返回可核验的番号，不能用用户输入替代缺失身份。
5. 按字段优先级合并，保留封面/海报候选和来源资料。图片层另行检查响应、摘要、尺寸，不能仅因 URL 存在就视为下载成功。

站点改版应修改对应规则并运行保存的测试样本；无法通过登录或验证页时给出原因，不伪造资料。商业来源凭据由用户在安装后的设置中提供。

模板组件的许可声明保留在 `ui/lib/vendor/`。
